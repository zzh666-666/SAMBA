# 基于 CSMD 的分阶段新闻增强 SAMBA 实验方案

## 1. 研究目标

本文面向 `CSMD300/CSMD50` 中文股票多模态数据集，研究如何在保留 `SAMBA` 时序-图建模主干的基础上，逐步引入新闻信息，以提升下一交易日收益率与涨跌方向预测性能。与一次性叠加多种复杂机制不同，本文采用分阶段实验设计：首先建立稳定的价格基线模型，然后按照“日级新闻表示 -> 结构化新闻因子 -> 跨模态对齐 -> 新闻节点入图”的顺序逐步增强模型能力。该设计的核心目标有三点：

1. 保证实验路径清晰，可逐步定位性能收益来源；
2. 保证每一步创新均与 `CSMD` 数据特征相匹配，而非机械移植其他任务中的复杂结构；
3. 在控制实验复杂度的前提下，优先选择最有可能带来稳定性能提升的新闻增强机制。

---

## 2. 数据集与任务设定

### 2.1 数据来源

正式实验数据采用：

`Graph_SAMBA/data/raw_data/CSMD300`

辅助稳健性验证数据采用：

`Graph_SAMBA/data/raw_data/CSMD50`

其中，`CSMD300` 包含 300 只股票的价格与新闻数据，`CSMD50` 与其同源，适合作为缩小规模的辅助验证集。根据当前数据检查结果，新闻与价格数据的主要时间范围覆盖 `2021-01-04` 至 `2024-12-31`。

### 2.2 任务定义

本文统一采用日频预测设定：在交易日 `t` 收盘后，使用截至 `t` 的价格与新闻信息，预测 `t+1` 的市场表现。为保证结果可与已有股票预测工作对齐，本文同时设置如下两个预测任务：

1. **收益率回归任务**

   `r_{s,t+1} = log(Close_{s,t+1} / Close_{s,t})`

2. **涨跌方向分类任务**

   `y_{s,t+1} = 1 if r_{s,t+1} > 0 else 0`

### 2.3 时间切分

本文采用严格时间切分，避免前视偏差：

| 数据划分 | 时间范围 |
|---|---|
| Train | 2021-01-04 至 2022-12-31 |
| Valid | 2023-01-01 至 2023-12-31 |
| Test | 2024-01-01 至 2024-12-31 |

### 2.4 CSMD 数据特点与实验约束

当前 `CSMD` 数据具有如下关键特点：

1. 价格数据为标准日频时间序列，适合直接构造窗口样本；
2. 新闻也是以交易日为核心时间粒度组织，因此新闻必须对齐到 `(ticker, trading_date)` 层面；
3. 根据新闻统计结果，`CSMD300` 与 `CSMD50` 中单只股票单日新闻数量上限均为 `3`；
4. 因此，本文不采用长文本新闻集合设定，而采用更符合数据实际分布的**固定 3 槽位日级新闻袋**。

这意味着本文的新闻创新必须优先围绕“**日级聚合、结构化因子、低复杂度稳定融合**”展开，而不应一开始引入过多跨股票、跨图、跨层级复杂机制。

### 2.5 价格侧时序数据扩维

为了使 `SAMBA` 更充分地利用 `CSMD` 的价格信息，本文不直接以原始 `OHLCV` 五维向量作为唯一输入，而是在严格遵守无前视偏差原则的前提下，对价格侧时间序列进行因子扩维。该步骤并非引入新的预测目标，而是将原始日频价格记录转换为更适合时序建模的多因子表示。

原始价格字段包括：

1. `Date`
2. `Open`
3. `High`
4. `Low`
5. `Close`
6. `Adj Close`
7. `Volume`

在此基础上，本文将价格侧扩展为约 20 个价格/技术因子，具体包括：

| 类别 | 代表特征 |
|---|---|
| 原始价格量 | `Open`, `High`, `Low`, `Close`, `Adj Close`, `Volume` |
| 收益与趋势 | `ret_1`, `ret_3`, `ret_5`, `ma_5`, `ma_10`, `ema_5`, `ema_10` |
| 波动与区间 | `rolling_std_5`, `rolling_std_10`, `atr`, `high_low_spread` |
| 成交活跃 | `vol_chg`, `volume_ma_5`, `volume_ratio` |
| 动量 | `rsi`, `macd_hist` |

其中，`ret_k` 表示过去 `k` 日收益率，`ma/ema` 表示移动均值与指数移动均值，`rolling_std` 与 `atr` 则用于描述短期波动性。该设计主要参考先前重设计方案中的价格预处理思路，其核心目的是通过时序扩维增强价格分支对趋势、波动、成交活跃度与动量模式的表达能力。

为了保证实验严谨性，价格侧扩维需遵守以下规范：

1. 任一交易日 `t` 的特征只能由 `t` 及以前数据计算得到；
2. 标准化器仅在训练集拟合，验证集与测试集只进行变换；
3. 标签列不得泄露到输入特征中；
4. 所有股票均按各自交易日历对齐，再统一进入窗口构造。

处理完成后，价格数据被组织为：

`(ticker, trading_date) -> [price_features_{s,t}, target_return_{s,t+1}, target_cls_{s,t+1}]`

这一步的直接产物是：

`processed/price_features.parquet`

### 2.6 新闻数据处理

考虑到本文推荐的主实验线以“日级新闻向量 + 结构化新闻因子增强”为核心，因此新闻数据处理也应围绕这一目标展开。新闻侧预处理采用“清洗 -> 单条编码 -> 同日聚合 -> 日级统计”的标准流程。

#### 2.6.1 新闻清洗

原始新闻字段主要包括：

1. `code_name`
2. `ticker`
3. `created_at`
4. `text`

清洗规则如下：

1. 删除空文本与异常短文本；
2. 按 `ticker + created_at + text` 去重；
3. 保留原始文本 `text_raw` 与清洗文本 `text_clean`；
4. 将新闻日期统一映射到 `trading_date`。

该步骤产物为：

`processed/news_item_clean.parquet`

#### 2.6.2 固定 3 槽位新闻袋

根据当前 `CSMD300` 与 `CSMD50` 的统计结果，单只股票单个交易日新闻数量上限均为 `3`。因此，本文不采用其他数据集常见的长新闻集合设定，而采用**固定 3 槽位新闻袋**：

1. 设 `M=3`；
2. 若某日新闻数为 `1` 或 `2`，则补零到 3 条；
3. 若某日无新闻，则保留该交易日，并令 3 个槽位全为零；
4. 记录对应的新闻掩码 `news_mask`。

于是，任一 `stock-day` 的新闻输入可表示为：

`E_{s,t} ∈ R^{3 × d},  M_{s,t} ∈ {0,1}^3`

该设计完全贴合 `CSMD` 的真实新闻分布，是本文新闻侧所有方案的共同输入基础。

#### 2.6.3 单条新闻编码

对单条新闻 `d_{s,t,i}`，本文采用“两通道”编码方式：

1. **语义向量通道**
   将新闻文本编码为连续向量 `news_embed`，用于保留整体语义信息；
2. **结构化因子通道**
   从新闻中提取：
   - `sentiment_score`
   - `materiality_score`
   - `event_type`
   - `factor_text_top3`

其中，`sentiment_score` 用于刻画利好/利空倾向，`materiality_score` 用于衡量新闻对股价潜在影响强弱，`event_type` 反映事件类别，`factor_text_top3` 用于保留可解释影响摘要。

该步骤产物为：

`processed/news_item_features.parquet`

#### 2.6.4 日级新闻聚合

在单条新闻编码完成后，对同一 `(ticker, trading_date)` 下的 1-3 条新闻进行日级聚合，得到：

1. **日级新闻向量**

   `z_news_{s,t}`

2. **结构化日级统计量**

   - `news_count`
   - `sentiment_mean`
   - `sentiment_extreme`
   - `materiality_mean`
   - `materiality_max`
   - `event_performance`
   - `event_policy`
   - `event_risk`
   - `mask_news`

在推荐主实验线中，同日聚合优先采用两类低复杂度策略：

1. `MeanPool`
2. `Materiality-weighted Pool`

前者用于构造最弱新闻基线，后者用于体现“重要新闻应获得更高权重”的设计思想。该阶段的直接产物为：

`processed/news_day_features.parquet`

### 2.7 单日样本构造与窗口生成

在价格侧扩维和新闻侧聚合完成后，本文将所有数据统一到 `(ticker, trading_date)` 层面，并构造多模态单日样本：

`sample_{s,t} = [price_features_{s,t}, z_news_{s,t}, news_stats_{s,t}, y_{s,t+1}]`

其中：

1. `price_features_{s,t}` 为价格扩维后的因子向量；
2. `z_news_{s,t}` 为日级新闻向量；
3. `news_stats_{s,t}` 为显式新闻统计因子；
4. `y_{s,t+1}` 为下一交易日的监督标签。

进一步地，使用长度为 `L` 的滚动窗口构造模型输入：

`[sample_{s,t-L+1}, ..., sample_{s,t}]`

最终形成：

1. `X_price ∈ R^{L × F_p}`
2. `X_news ∈ R^{L × F_n}`
3. `M_news ∈ R^{L}`
4. 在方案4及以后，构造图输入 `X_factor`

### 2.8 预处理产物总结

综上，本文的数据集处理最终形成以下四类中间产物：

1. `processed/price_features.parquet`
2. `processed/news_item_clean.parquet`
3. `processed/news_item_features.parquet`
4. `processed/news_day_features.parquet`

在进一步和价格数据完全对齐后，可生成：

`processed/aligned_daily_samples.parquet`

这些产物共同构成后续所有实验方案的统一数据基础。

## 3. 模型设计原则

为了使实验方案既具备研究价值，又具备现实可执行性，本文提出如下模型设计原则：

### 3.1 保留 SAMBA 主干

`SAMBA` 已经验证了 `BI-Mamba + 图建模` 在股票时间序列预测中的有效性。因此，价格侧主干不宜大幅改写。本文所有增强模型均以 `SAMBA` 作为基础骨架，避免重新发明价格编码器。

### 3.2 价格侧先做低风险扩维，再做新闻增强

本文认为“时序扩维”首先应理解为价格侧多因子扩展，而不是简单把新闻向量直接拼接到 `OHLCV` 后面。由于 `CSMD` 的价格数据稳定、规范、连续，因此首先对价格侧进行技术指标扩维，能够为 `SAMBA` 主干提供更丰富的时序模式输入，也能为后续新闻融合建立更强的对照基线。

### 3.3 新闻创新优先选择最适配 CSMD 的机制

新闻增强不以“模块数量最多”为目标，而以“最匹配 CSMD 数据特点、最有可能稳定提升结果”为目标。考虑到 `CSMD` 单股单日新闻数很少，最先应引入的创新不应是跨股票因果图或复杂原型层，而应是：

1. 单条新闻的结构化因子提取；
2. 同日 1-3 条新闻的合理聚合；
3. 新闻与价格在日频层面的稳定融合。

### 3.4 分阶段验证收益来源

一次性同时引入多种创新，会导致实验结果难以解释。因此本文采用**逐层增强**策略，使每个新增模块都能通过消融实验回答两个问题：

1. 该模块是否带来了性能提升；
2. 该性能提升是否足够稳定且具有可解释性。

## 4. 分阶段实验方案设计

本文将实验方案划分为六类，按照推荐顺序依次引入。前四类构成论文主实验线，第五、六类属于增强实验或扩展实验。

### 4.1 方案0：SAMBA 价格基线

#### 4.1.1 方案内容

方案0仅使用价格数据与技术指标构造输入，不引入任何新闻信息。该方案用于建立后续所有新闻增强模型的比较基准。

#### 4.1.2 具体步骤

1. 从 `CSMD300` 价格文件中提取：
   `Open, High, Low, Close, Adj Close, Volume`
2. 依据第 2.5 节对价格侧进行时序扩维，构造收益、趋势、波动、成交活跃与动量特征；
3. 生成价格因子表：
   `processed/price_features.parquet`
4. 以窗口长度 `L` 构造价格时序样本：
   `X_price ∈ R^{L × F_p}`
5. 将价格特征输入 `SAMBA` 价格流：
   `线性投影 -> BI-Mamba -> AGC`
6. 输出：
   - `pred_return`
   - `pred_direction`

#### 4.1.3 理论依据

该方案直接参考 `SAMBA` 的价格时序建模主干，是本文所有新闻增强实验的基础对照模型。

#### 4.1.4 可行性评估

该方案实现难度最低、稳定性最高，且有助于验证：

1. 价格预处理是否正确；
2. 标签定义是否正确；
3. `SAMBA` 主干在当前数据上的可运行性与基础性能。

#### 4.1.5 作用定位

方案0不是创新模型，但必须作为所有实验的基线存在。

---

### 4.2 方案1：日级新闻向量增强 SAMBA

#### 4.2.1 方案内容

方案1在价格基线的基础上，引入**日级新闻向量**作为第二路输入。该方案是最小新闻增强版本，也是最适合作为第一创新实验的方案。

#### 4.2.2 具体步骤

1. 对单条新闻编码，生成：
   - `news_embed`
   - `sentiment_score`
   - `materiality_score`
   - `event_type`
2. 按第 2.6.2 节将同日新闻组织为固定 3 槽位新闻袋，并保留 `news_mask`；
3. 对同一 `(ticker, trading_date)` 下的 1-3 条新闻进行聚合；
4. 得到日级新闻表示：
   `z_news_{s,t}`
5. 生成日级新闻表：
   `processed/news_day_features.parquet`
6. 构造新闻序列输入：
   `X_news ∈ R^{L × F_n}`
7. 使用轻量 `GRU` 或轻量 `BI-Mamba` 编码新闻日级序列，得到：
   `h_news`
8. 与价格流表示 `h_price` 进行简单门控融合：

   `g = sigmoid(W[h_price; h_news; mask_news])`

   `h_fused = h_price + g * h_news`

9. 使用 `h_fused` 输出收益率与方向预测。

#### 4.2.3 理论依据

该方案综合参考两类工作：

1. `CSMD`：新闻应提取为可解释的金融相关因子，而不是保留为原始文本；
2. `M2VN`：时间序列模态与文本模态应采用双流表示，而不应直接在原始输入层简单拼接。

#### 4.2.4 为什么适合 CSMD

该方案最适配 `CSMD` 的原因在于：

1. `CSMD` 是日频任务，新闻天然需要聚合到交易日级别；
2. `CSMD` 单股单日新闻数量极少，因此简单稳定的聚合通常比复杂长文档建模更有效；
3. 该方案不改动 `SAMBA` 的图结构主干，只在其旁增加一条新闻分支，工程风险较低。

#### 4.2.5 可行性评估

该方案的实现难度较低，适合作为第一个新闻增强实验。其主要风险在于：如果单条新闻编码器质量不足，或者融合层过于简单，则新闻收益可能被价格流淹没。

#### 4.2.6 研究价值

方案1的主要价值在于回答最基础但最关键的问题：

**在保留 SAMBA 主干不变的前提下，CSMD 的日级新闻信息本身是否能够带来稳定增益。**

---

### 4.3 方案2：结构化新闻因子增强 SAMBA

#### 4.3.1 方案内容

在方案1中，新闻主要通过日级新闻向量 `z_news_{s,t}` 进入模型。方案2进一步引入显式结构化新闻因子，使新闻不只以黑盒向量形式参与融合，而是以“语义表示 + 金融解释因子”的联合形式参与建模。

#### 4.3.2 具体步骤

在方案1基础上，除了保留 `z_news_{s,t}`，还显式保留：

1. `news_count`
2. `sentiment_mean`
3. `sentiment_extreme`
4. `materiality_mean`
5. `materiality_max`
6. `event_performance`
7. `event_policy`
8. `event_risk`

然后采用以下两种方式之一融合：

1. **作为新闻流输入的一部分**

   `x_news_day = [z_news_{s,t}; stats_{s,t}]`

2. **作为门控融合层的额外输入**

   `g = sigmoid(W[h_price; h_news; news_stats])`

在数据组织上，方案2使用第 2.6.4 节生成的日级统计量，并将其与价格因子表在 `(ticker, trading_date)` 层面进行对齐。最终输出仍为收益率与方向预测。

#### 4.3.3 理论依据

该方案主要参考：

1. `CSMD`：强调抽取 `interpretable, salient, impactful` 的新闻因素；
2. `FinReport`：强调新闻不应只作为文本语义向量使用，而应进一步转换为可分析、可解释的因子表示。

#### 4.3.4 为什么适合 CSMD

该方案比方案1更适合论文主线，原因在于：

1. `CSMD` 本身就强调新闻因子的可解释性；
2. 单日最多 3 条新闻的场景下，`sentiment`、`materiality` 与 `event_type` 往往比复杂深层语义交互更直接有效；
3. 即使新闻整体向量收益不明显，显式结构化因子也可能为模型提供稳定信号。

#### 4.3.5 可行性评估

该方案的实现难度仍然较低。相比方案1，其主要新增成本在于：

1. 需要保证新闻因子提取逻辑稳定；
2. 需要设计合适的显式因子融合方式。

总体来看，方案2在“效果、解释性、实现难度”三者之间取得了较好的平衡。

#### 4.3.6 研究价值

方案2能够进一步回答：

**新闻对价格预测的增益，究竟来自整体语义表示，还是来自情绪、材料性、事件类型等结构化因素。**

---

### 4.4 方案3：价格-新闻对齐增强 SAMBA

#### 4.4.1 方案内容

方案3在方案2基础上引入跨模态对齐约束，使价格流与新闻流不仅在输出层融合，还在表示空间中形成一致的语义映射关系。

#### 4.4.2 具体步骤

1. 使用价格流得到：
   `h_price_{s,t}`
2. 使用新闻流得到：
   `h_news_{s,t}`
3. 构造正负样本对：
   - 正样本：同一股票、同一交易日
   - 负样本：不同股票或不同日期
4. 引入 `InfoNCE` 对齐损失：

   `L = L_pred + λ L_align`

5. 在联合训练中同时优化预测损失与对齐损失。

#### 4.4.3 理论依据

该方案直接参考 `M2VN` 的多模态对齐思路。该工作明确指出，文本模态与时序模态应通过辅助对齐损失约束到一致语义空间，以提升融合稳定性。

#### 4.4.4 为什么适合 CSMD

该方案适合 `CSMD`，因为：

1. `CSMD` 新闻与价格都可以精确对齐到交易日级别；
2. 对齐目标明确，不存在过强的时间模糊性；
3. 当新闻分支已具备较好的日级表示后，对齐约束有机会进一步提高多模态协同学习能力。

#### 4.4.5 可行性评估

该方案的实现复杂度显著高于方案1和方案2，但仍属于可控范围。其风险主要在于：

1. 对齐损失权重 `λ` 需要调节；
2. 如果新闻表示质量不足，对齐项可能引入训练不稳定性。

#### 4.4.6 研究价值

方案3适合作为第二层创新，用于回答：

**价格与新闻的联合建模，是“简单融合”更有效，还是“对齐后融合”更有效。**

---

### 4.5 方案4：显式新闻因子节点入图

#### 4.5.1 方案内容

方案4开始真正修改 `SAMBA` 图模块本身：将新闻显式因子转换为图节点，与价格节点和技术指标节点共同进入 `AGC + BI-Mamba` 模块。

#### 4.5.2 具体步骤

1. 保留原始价格节点与技术指标节点；
   其中价格节点直接来自第 2.5 节生成的价格扩维因子；
2. 加入新闻显式节点：
   - `news_count`
   - `sentiment_mean`
   - `sentiment_extreme`
   - `materiality_mean`
   - `materiality_max`
   - `event_performance`
   - `event_policy`
   - `event_risk`
3. 构造联合节点序列：

   `x_{s,t} = [price_nodes_{s,t}; news_nodes_{s,t}]`

4. 输入 `AGC + BI-Mamba`
5. 学习：
   - 价格节点之间关系
   - 新闻节点之间关系
   - 价格节点与新闻节点之间关系

#### 4.5.3 理论依据

该方案主要参考：

1. `SAMBA`：特征图建模主干；
2. `FinReport`：新闻应先因子化，再与股票因子共同进入建模流程。

#### 4.5.4 为什么适合 CSMD

该方案能够进一步提升新闻的结构化利用程度，但前提是前面已经证明新闻因子本身有效。换言之，方案4更适合作为中后期增强模型，而不应作为最初实验入口。

#### 4.5.5 可行性评估

该方案的实现复杂度中等偏高，因为它需要修改 `SAMBA` 的图输入定义与节点组织方式。若新闻节点噪声较大，则可能影响图结构学习稳定性。

#### 4.5.6 研究价值

方案4的核心价值在于使新闻从“辅助分支输入”升级为“图结构中的因子节点”，更适合形成较强的论文创新表达。

---

### 4.6 方案5：隐式新闻原型节点增强

#### 4.6.1 方案内容

在方案4基础上，将日级新闻向量 `z_news_{s,t}` 投影为若干原型节点：

`news_proto_1, ..., news_proto_K`

以增强新闻侧潜在语义表示能力。

#### 4.6.2 理论依据

该方案仅借鉴 `TIME-LLM` 的原型化思想，而不使用其完整模型主干。

#### 4.6.3 可行性评估

该方案实现上并不困难，但研究风险较高：

1. 原型节点的解释性弱于显式节点；
2. 如果前面显式节点建模尚未稳定，过早加入原型节点容易引入噪声。

#### 4.6.4 使用建议

方案5不建议进入首轮主实验，更适合作为增强实验或附录实验。

---

### 4.7 方案6：跨股票 transfer entropy 因果增强

#### 4.7.1 方案内容

在完整 `CSMD300` 股票池上，利用历史收益率构建 `transfer entropy` 因果矩阵 `C_t`，并将其作为跨股票增强信号引入模型。

#### 4.7.2 理论依据

该方案参考 `CMIN` 对股票间因果关系的建模方式，但仅借用 `transfer entropy` 机制，不照搬其完整 memory network 主体。

#### 4.7.3 可行性评估

该方案是所有扩展中实现复杂度最高的一项。其主要问题包括：

1. 计算代价高；
2. 调参复杂；
3. 一旦结果不稳定，很难快速定位问题来源。

#### 4.7.4 使用建议

方案6不适合作为当前论文主线，应仅作为完整模型扩展，且放在所有单股票新闻增强实验完成之后再考虑。

---

## 5. 推荐主实验线

综合考虑 `CSMD` 数据特点、工程可行性与结果稳定性，本文推荐如下主实验线：

### 5.1 主实验顺序

1. **方案0：SAMBA 价格基线**
2. **方案1：日级新闻向量增强**
3. **方案2：结构化新闻因子增强**
4. **方案3：价格-新闻对齐增强**

在数据处理层面，上述四个主实验方案共享同一套预处理管线：

1. 先完成价格侧时序扩维；
2. 再完成新闻清洗、单条编码与日级聚合；
3. 再统一构造 `(ticker, trading_date)` 级单日样本；
4. 最后按窗口长度 `L` 构造多模态时序输入。

这样设计的好处在于，不同方案之间的差异主要来自模型层，而不是来自不一致的数据处理过程。

### 5.2 推荐主模型

若当前只能选择一个最适合作为正式主模型的方案，本文推荐：

**方案2：结构化新闻因子增强 SAMBA**

其原因在于：

1. 与 `CSMD` 数据适配性最高；
2. 比方案1具有更强解释性；
3. 比方案3、4、5、6 风险显著更低；
4. 在“性能提升、解释能力、实现复杂度”三者之间平衡最佳。

### 5.3 增强实验线

在主模型跑通并得到稳定结果后，可进一步按如下顺序扩展：

1. 加入对齐损失（方案3）
2. 加入显式新闻节点入图（方案4）
3. 加入原型节点（方案5）
4. 最后考虑跨股票因果增强（方案6）

---

## 6. 消融实验设计

为了清晰评估每个模块的贡献，本文建议进行如下消融实验：

### 6.1 新闻是否有效

1. `SAMBA price-only`
2. `SAMBA + z_news`

用于验证新闻模态是否带来基础增益。

### 6.2 聚合方式是否重要

1. `MeanPool`
2. `Materiality-weighted Pool`

用于验证材料性加权是否优于简单平均。

### 6.3 结构化因子是否有效

1. 仅使用 `z_news`
2. `z_news + sentiment`
3. `z_news + materiality`
4. `z_news + event_type`
5. `z_news + 全部结构化因子`

用于验证不同显式因子的独立贡献。

### 6.4 对齐损失是否有效

1. 不加 `InfoNCE`
2. 加 `InfoNCE`

用于验证跨模态对齐的有效性与稳定性。

### 6.5 图节点扩展是否有效

1. 仅价格节点
2. 价格节点 + 显式新闻节点
3. 价格节点 + 显式新闻节点 + 原型节点

用于验证新闻节点是否真正为图建模带来增益。

## 7. 可行性与风险评估

从整体可行性看，当前方案不宜一开始就选择方案4、5、6作为主实验线。原因在于，这些方案虽然理论上更“复杂”、更“完整”，但对于当前研究阶段而言存在明显风险：

1. 创新点过多，难以定位收益来源；
2. 模型改动范围过大，工程实现成本高；
3. 一旦性能不佳，难以判断是新闻表示问题、融合问题、图结构问题还是因果层问题。

相比之下，方案1和方案2更符合当前阶段的研究目标。它们既能够体现 `CSMD` 数据集上的新闻创新，又不会破坏 `SAMBA` 主干的稳定性，因此更适合作为正式论文主线。

---

## 8. 最终建议

本文最终建议采用如下研究策略：

1. 以 `SAMBA` 为价格时序与图结构主干；
2. 第一阶段只引入**日级新闻表示**；
3. 第二阶段引入**结构化新闻因子**；
4. 第三阶段再引入**跨模态对齐损失**；
5. 只有在前三阶段结果稳定后，才考虑**新闻因子节点入图**与**跨股票因果增强**。

换言之，当前最合理的创新路径不是“在 `SAMBA` 中一次性融入尽可能多的新模块”，而是：

**围绕 `CSMD` 数据集的真实特点，从最小、最稳、最可解释的新闻增强开始，逐步推进到更复杂的多模态图建模方案。**

这一分阶段设计既有助于获得更可靠的实验结论，也更符合计算机论文对方法来源清晰性、实验可复现性与创新边界明确性的要求。
